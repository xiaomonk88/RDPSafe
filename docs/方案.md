# RDPSafe 开发方案（RDP 防暴力破解工具）

> 依据 `参考/` 目录 6 张截图分析整理。目标：功能与界面 1:1 复刻，并在架构上补齐原版的短板。

---

## 一、原版功能拆解（截图逆向）

| 模块 | 截图中的功能点 |
|---|---|
| **顶栏** | 盾牌 Logo + “RDPSafe”；右侧实时状态 `状态: 监控中 — 最近处理 N 条事件` |
| **仪表盘** | 4 张统计卡片：今日失败(红) / 活跃封禁(橙) / 今日成功(绿) / 失败 IP 数(蓝)；左侧“运行状态”文本面板（引擎状态、最后事件时间、今日登录/失败/成功、失败 IP 数、活跃封禁、今日新增封禁、当前策略、解封策略）；右侧“封禁策略”：最大失败次数(3)、时间窗口分钟(120)、轮询间隔秒(5)、日志保留小时(96)、自动解封开关 + 封禁时长小时(24)、开机自动启动、保存设置 |
| **登录记录** | IP 筛选框、全部/失败/成功 单选、查询、清除全部日志、“● 实时”指示、封禁选中 IP；表格：时间 / 来源 IP / 国家 / 用户名 / 结果（失败红色 ✕） |
| **封禁管理** | 刷新、活跃封禁/全部记录 单选、解封选中；表格：IP / 国家 / 封禁时间 / 解封时间(永久) / 原因(auto) / 状态(● 封禁中) |
| **黑白名单** | 左：手动黑名单（永久封禁）IP+备注+添加，表格 IP/国家/封禁时间/备注，“移除并解封选中”；右：IP 白名单（永不封禁）IP+备注+添加，表格 IP/国家(含省份)/备注，“移除选中”；登录记录中右键可加入白名单 |
| **防火墙规则** | 刷新、新建规则、修改选中、启用/禁用、删除选中；名称筛选 + 搜索；全部/阻止/允许；表格：规则名称/状态/操作/协议/本地端口/远程 IP（管理系统全部入站规则，183 条） |
| **操作日志** | 刷新；封禁/解封/白名单等操作及引擎周期日志（“处理了 N 条新事件”、“自动清理了 30 条超过 96 小时的日志”） |
| **状态栏** | 当前页加载信息：“已加载 500 条登录记录 / 8 条封禁记录 / 183 条防火墙入站规则” |

**原版推断的短板**（新版要改进）：
1. “以管理员权限**登录时**自动运行”——服务器重启后、无人登录期间**完全不防护**，而这恰恰是被爆破最多的时段。
2. 5 秒轮询事件日志，延迟高、CPU 浪费。
3. 大概率“一 IP 一条防火墙规则”，封禁上千 IP 后防火墙规则膨胀、性能下降。
4. 开启 NLA 时 4625 事件常出现 IP 为 `-`，原版“国家：未知”较多，可能存在漏抓。

## 二、技术选型（推荐）

| 层 | 选型 | 理由 |
|---|---|---|
| 语言/运行时 | **C# / .NET 8** | 原生访问 Windows 事件日志、防火墙 COM、服务框架；单文件发布 |
| 界面 | **WPF + CommunityToolkit.Mvvm** | 可精确复刻截图的扁平风格（卡片、彩色按钮、Tab 样式），DataGrid 虚拟化支撑上万行 |
| 后台引擎 | **Windows Service**（`Microsoft.Extensions.Hosting.WindowsServices`） | 开机即运行、无需登录、LocalSystem 权限 |
| 存储 | **SQLite (WAL 模式)** + `Microsoft.Data.Sqlite` + Dapper | 零部署；WAL 允许 GUI 并发读 |
| 进程通信 | **Named Pipe + JSON**（`\\.\pipe\RDPSafe`），ACL 仅限 Administrators | GUI 下发命令给服务 |
| 事件读取 | `System.Diagnostics.Eventing.Reader.EventLogWatcher`（订阅推送）+ Bookmark | 实时、断点续读 |
| 防火墙 | `INetFwPolicy2` COM（HNetCfg.FwPolicy2） | 比调用 `netsh` 快两个数量级，可读全部规则 |
| IP 归属地 | **ip2region (xdb，离线)** | 直接输出中文“美国 华盛顿州”，与截图一致，微秒级查询 |
| 打包 | `dotnet publish -r win-x64 --self-contained -p:PublishSingleFile=true` + Inno Setup 安装包 | 安装时注册服务、开启审核策略 |

> 备选：若追求最快出原型，可用 Python + tkinter + pywin32 + PyInstaller（原版很可能就是这么做的，界面控件风格就是 Tk/ttk），但服务化、性能和界面质感都不如上面方案。

## 三、总体架构

```
┌──────────────────────── RDPSafe.exe (GUI, requireAdministrator) ───────────────────────┐
│ 仪表盘 │ 登录记录 │ 封禁管理 │ 黑白名单 │ 防火墙规则 │ 操作日志                          │
│   ViewModels ──读──► SQLite(WAL, 只读连接)                                              │
│   ViewModels ──命令──► NamedPipe Client ──────────────┐                                 │
│   防火墙规则页 ──直接──► FirewallService(COM)         │                                 │
└───────────────────────────────────────────────────────┼─────────────────────────────────┘
                                                        ▼
┌──────────────── RDPSafe.Service.exe (Windows 服务, LocalSystem, 自动启动) ───────────────┐
│ EventCollector ─► Detector ─► BanManager ─► FirewallService(聚合规则)                     │
│      ▲ (4624/4625/RdpCoreTS 140)   │               │                                     │
│  EventLogWatcher + Bookmark        ▼               ▼                                     │
│                              SQLite(唯一写入方)   OpLogger                                │
│ Scheduler: 到期解封(1min) / 日志清理(1h) / 防火墙对账(启动+10min)                         │
│ PipeServer: Ban/Unban/AddWhite/AddBlack/SaveSettings/ClearLogs/GetStatus                 │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

原则：**服务是唯一的数据写入方和封禁执行方**，GUI 关掉不影响防护；GUI 只负责展示和下发命令（防火墙规则页的通用规则管理除外，由 GUI 直接调用 COM）。

## 五、核心实现要点

### 5.1 事件采集（最关键）

前置条件：开启登录审核（安装时自动执行，并在仪表盘检测、未开启时红色提示）：
```
auditpol /set /subcategory:"Logon" /success:enable /failure:enable
```

订阅的事件源：

| 日志 | 事件 ID | 用途 |
|---|---|---|
| Security | **4625** | 登录失败：`IpAddress`、`TargetUserName`、`LogonType`(3=NLA网络 / 10=远程交互)、`SubStatus` |
| Security | **4624** | 登录成功，过滤 `LogonType=10`，或 `LogonType=3` 且 `IpAddress` 为外部地址 |
| Microsoft-Windows-RemoteDesktopServices-RdpCoreTS/Operational | **140** | “来自 IP x.x.x.x 的连接因用户名或密码错误失败”——**补齐 NLA 下 4625 IP 为 `-` 的情况** |
| 同上 | 131 | 连接建立（可选，用于关联/统计） |

XPath 示例：
```xml
<QueryList><Query Id="0">
  <Select Path="Security">*[System[(EventID=4625 or EventID=4624)]]</Select>
  <Select Path="Microsoft-Windows-RemoteDesktopServices-RdpCoreTS/Operational">*[System[(EventID=140)]]</Select>
</Query></QueryList>
```

实现：
- `EventLogWatcher` 订阅推送 → 写入 `Channel<LoginEvent>`，后台单消费者批量处理（每 N 条或 500ms 一批，一个事务写库），日志“处理了 N 条新事件”。
- 每批处理后保存 **Bookmark**；服务重启时从书签续读，不漏不重。
- “轮询间隔(秒)”保留为兜底：订阅异常（如日志被清空）时降级为按 `RecordId` 增量轮询。
- 过滤：IP 为 `-`/`127.0.0.1`/`::1`/本机地址跳过；IPv6 映射地址 `::ffff:x.x.x.x` 归一化。

### 5.2 检测算法

```
OnFailure(ip, user, time):
    if Whitelist.Match(ip): return              # 支持单 IP 与 CIDR
    if Bans.IsActive(ip):   return
    window = failures[ip]                       # 内存 Deque<DateTime>，启动时从 DB 预热
    window.Push(time); 移除 time - WindowMinutes 之前的项
    if window.Count >= MaxFailures:
        Ban(ip, reason="auto", expire = AutoUnban ? now + BanHours : null)
        window.Clear()
```
- 默认值与截图一致：3 次 / 120 分钟 / 轮询 5 秒 / 保留 96 小时 / 自动解封关 / 24 小时 / 开机自启开。
- 成功登录不清零失败计数（防止“猜中前混入一次正常登录”绕过），可做成选项。
- **防自锁**：白名单为空时首次启动，自动把“当前 RDP 会话的客户端 IP”加入白名单并提示（截图白名单中的“右键添加”同理）。

### 5.3 防火墙封禁（聚合规则）

- 不再一 IP 一规则，而是规则组 `RDPSafe_Block_001…N`，每条 `RemoteAddresses` 承载最多 **1000** 个 IP/CIDR，方向入站、动作阻止、协议任意（全端口封锁，防止换端口探测）。
- 封禁/解封只修改对应规则的地址串，O(1) 级 COM 调用；手动黑名单使用独立组 `RDPSafe_Black_*`，便于区分。
- **对账**：服务启动及每 10 分钟，以 DB 中活跃封禁为准重建 RDPSafe 规则组，防止被人工删除或第三方软件改动。
- 封禁后可选断开该 IP 已建立的 RDP 会话/TCP 连接（`SetTcpEntry` 置 DELETE_TCB），避免已连上的会话继续尝试。

### 5.4 防火墙规则页（通用规则管理）

- `INetFwPolicy2.Rules` 枚举，筛选 `Direction == IN`，列：名称、启用、动作、协议(6=TCP/17=UDP/256=任意)、本地端口、远程地址。
- 新建/修改对话框：名称、方向、动作、协议、本地端口、远程 IP、配置文件(域/专用/公用)、启用。
- 删除系统规则前二次确认；RDPSafe 自身规则在此页只读（标灰），避免与引擎冲突。
- 名称筛选 + 全部/阻止/允许 在内存中过滤，DataGrid 虚拟化。

### 5.5 IP 归属地

- ip2region `xdb` 文件以 `VectorIndex` 或全量内存缓存模式加载，查询结果解析为“国家 省份”；内网 IP 显示“局域网”，查不到显示“未知”。
- 结果冗余存入 `login_events.country`、`bans.country`，界面无需重复查询。

### 5.6 自动任务

| 任务 | 周期 | 说明 |
|---|---|---|
| 到期解封 | 1 分钟 | `expire_at <= now` 的封禁置为已解封并移出防火墙，写操作日志 |
| 日志清理 | 1 小时 | 删除超过“日志保留(小时)”的登录记录与操作日志，写“自动清理了 N 条…” |
| 防火墙对账 | 启动 + 10 分钟 | 见 5.3 |
| 统计快照 | 5 秒 | 写入内存状态，供 `GetStatus` 返回给顶栏/仪表盘 |

## 六、数据库设计（SQLite）

```sql
CREATE TABLE login_events(
  id INTEGER PRIMARY KEY, time INTEGER NOT NULL, ip TEXT NOT NULL,
  country TEXT, username TEXT, success INTEGER NOT NULL,
  logon_type INTEGER, source TEXT, record_id INTEGER);
CREATE INDEX ix_le_time ON login_events(time);
CREATE INDEX ix_le_ip_time ON login_events(ip, time);

CREATE TABLE bans(
  id INTEGER PRIMARY KEY, ip TEXT NOT NULL, country TEXT,
  ban_time INTEGER NOT NULL, expire_at INTEGER,          -- NULL = 永久
  unban_time INTEGER, reason TEXT NOT NULL,              -- auto / manual / blacklist
  active INTEGER NOT NULL DEFAULT 1);
CREATE UNIQUE INDEX ux_bans_active ON bans(ip) WHERE active = 1;

CREATE TABLE ip_lists(
  id INTEGER PRIMARY KEY, kind TEXT NOT NULL CHECK(kind IN ('black','white')),
  ip TEXT NOT NULL, country TEXT, note TEXT, created INTEGER NOT NULL,
  UNIQUE(kind, ip));

CREATE TABLE op_logs(id INTEGER PRIMARY KEY, time INTEGER NOT NULL, level TEXT, message TEXT NOT NULL);
CREATE INDEX ix_op_time ON op_logs(time);

CREATE TABLE settings(key TEXT PRIMARY KEY, value TEXT NOT NULL);
```

仪表盘统计 SQL（今日 = 本地时区 0 点起）：今日失败/成功 `COUNT ... WHERE time>=today GROUP BY success`；失败 IP 数 `COUNT(DISTINCT ip)`；活跃封禁 `COUNT(*) FROM bans WHERE active=1`；今日新增封禁 `ban_time>=today`。

## 七、IPC 协议（Named Pipe, JSON 行协议）

```json
{"cmd":"Ban","ip":"1.2.3.4","reason":"manual"}
{"cmd":"Unban","ips":["1.2.3.4"]}
{"cmd":"AddList","kind":"white","ip":"45.59.101.106","note":"右键添加"}
{"cmd":"RemoveList","kind":"black","ips":["..."],"unban":true}
{"cmd":"SaveSettings","settings":{...}}
{"cmd":"ClearLogins"}
{"cmd":"GetStatus"}   -> {"state":"监控中","lastEvent":"...","processed":1,"auditOk":true}
```
- 管道 ACL 仅 `BUILTIN\Administrators` 与 `SYSTEM`，防止低权限进程操纵封禁。
- 服务未运行时，GUI 顶栏显示红色“引擎未运行”，并提供“启动服务”按钮。

## 八、界面实现（WPF 复刻要点）

- 窗口 1080×760，最小 960×640；字体 `Microsoft YaHei UI` 10pt，表格数据用 `Consolas` 等宽（截图即如此）。
- 配色：顶栏 `#1E3A5F`；红 `#DC2626`；橙 `#D97706`；绿 `#059669`；蓝 `#2563EB`；页面底色 `#EEF2F7`；卡片白底 1px `#E2E8F0` 边框。
- 自定义 `TabControl` 样式：未选中灰底、选中白底蓝字，Tab 头含图标（Segoe Fluent Icons / Segoe MDL2 Assets）。
- DataGrid：`EnableRowVirtualization=True`，行高 28，无网格线；行前景色按结果绑定（失败红/成功绿/允许绿/阻止红）。
- 登录记录：默认加载最近 500 条（状态栏提示），“● 实时”开启时每 2 秒增量拉取 `id > lastId`；右键菜单：封禁此 IP / 加入白名单 / 复制 IP / 筛选此 IP。
- 设置项用 `NumericUpDown`（自写或 Extended.Wpf.Toolkit），自动解封未勾选时“封禁时长”禁用（截图中即灰色）。
- 托盘图标：最小化到托盘，新增封禁时气泡通知（可关闭）。
- `app.manifest` 设 `requireAdministrator`；单实例（Mutex）。

## 九、安装与部署

安装包（Inno Setup）执行：
1. 复制文件到 `C:\Program Files\RDPSafe\`；
2. `sc create RDPSafe binPath= "...\RDPSafe.Service.exe" start= delayed-auto`，配置失败自动重启（`sc failure`）；
3. 启用登录审核策略；增大 Security 日志上限（如 128MB），避免高频爆破下事件被覆盖；
4. 创建开始菜单/桌面快捷方式。

“开机自动启动”选项：控制的是**GUI 托盘**是否登录时启动（计划任务，最高权限）；**防护引擎始终以服务形式开机运行**。

卸载：停止并删除服务，询问是否删除 `RDPSafe_*` 防火墙规则与数据目录。

## 十一、测试方案

- **单元测试**：EventParser（用真实导出的 4625/4624/140 XML 样本）、滑动窗口边界、CIDR 匹配、白名单优先级、到期解封、聚合规则分组（第 1001 个 IP 落到第 2 条规则）。
- **集成测试**：Hyper-V 虚拟机内用 `hydra -t 4 rdp://` 或 `crowbar` 对测试机爆破，验证 3 次失败后被封、白名单 IP 永不被封、服务重启后封禁仍在。
- **压测**：注入 10 万条事件、1 万个封禁 IP，确认 GUI 流畅、CPU < 2%、防火墙规则数 ≤ 10 条。
- **故障测试**：删除 RDPSafe 防火墙规则 → 10 分钟内自动恢复；清空 Security 日志 → 采集不中断；杀掉 GUI → 防护不受影响。

## 十二、可选增强（v1.1+）

- 用户名策略：对 `admin/administrator/test` 等字典用户名“一次即封”。
- 网段封禁：同一 /24 内 ≥ N 个 IP 被封时自动封整个网段。
- 国家/地区策略：仅允许指定国家访问 RDP（基于 ip2region 生成白名单 CIDR）。
- 递增封禁：再次被封的 IP 时长翻倍（24h → 48h → 永久）。
- 通知：邮件 / 企业微信 / 钉钉 Webhook。
- 导入/导出黑白名单（txt/csv），共享社区黑名单订阅。
